## Function B · Navigation and recovery

- Landing links, auth redirects and account menu are full document navigations. Apache rewrites unmatched files/directories to `index.php` and has an explicit `.html` allowlist. The development router maps any `.html` basename and constructs a new Location without its query. A legacy editor ID, email state or template hint can therefore be lost locally. Protected page requests typically go to `/login` and then `/dashboard`; validated payment and store returns are special-cased. `builder` without ID resolves the current document from the dashboard or moves to a safe workspace destination. Browser back/refresh recovers saved server data; the cover-letter picker uses `history.replaceState()` so its selections do not form a back stack. The service worker caches allowlisted assets and offers a reconnect page, with no private document/API cache.
- Current candidate navigation is Resume, Cover letters and ReGen Store plus an account menu and one header bell. Mobile adds Resume, Letters, Store and Account as bottom destinations and uses editor-only controls instead in `/builder`. `mobile-viewport.js` tracks the visual viewport for keyboard/focus movement. The default active workspace section is Resume, so routes without an explicit mobile mapping, such as feedback, and secondary paths such as Mochi should be checked for clear current location. No viewport clipping or physical-device defect is claimed from code alone.
- Admin has one `/admin` shell. `admin.js::show()` switches Analytics (Overview/Reports/Traffic), User accounts (Accounts/Session controls), Feedback, Support, Campaigns, Pricing, Resume templates, AI usage, System settings (Feature availability/Access & sessions/Maintenance/Attachments), Mochi, Email (Test Email/Broadcast), Security monitor, Server status, Recovery, Administrators, Activity log and My profile. Alerts open from one header bell. No duplicated initial sidebar button IDs were found. Session controls and Server status share the operations scope and appear under different menu entries; Pricing retains two staff grant entry points across Pricing and User accounts with different capabilities. Current module/filter selection has no path or browser-history representation. Refresh or browser back cannot reliably restore a module; `/admin/{module}` has no page dispatch. Check delegated permissions, active-state accuracy, drawer keyboard/focus and tables at 360/390/768/1024/1440 px.
- `RealtimeEvents`, `RealtimeConnection`, `ManagedRealtime`, `realtime.js` and `live-notifications.js` provide per-principal topics, managed private authorization, cursor replay/poll fallback, and scoped alerts/unread counts. Admin `work-queues` counts open/in-progress tickets and new feedback only per module. Dirty admin forms get a refresh notice, while support refreshes in place. Historic November UAT reports draft preservation, counts and replies, but it is deployment-independent evidence. Provider disconnect/reconnect, delay and session revocation need fresh end-to-end checks.
- **Maintenance is partial.** `MaintenanceService::enforce()` is a page allowlist plus an API-prefix gate. `/mochi`, `/token-activity`, `/payments` and `/payments/result` are protected shells that are not in that allowlist. Their data APIs generally remain blocked. Browser realtime can redirect after entry, which leaves direct-page enforcement incomplete. The `render()` return allowlist is narrower again, so some gated pages cannot return to their prior destination. Admin access, public status, realtime recovery and signed payment callbacks have separate route ordering. Migrate these exceptions explicitly.

## Function C · Monetisation and money movement

1. Candidate opens **ReGen Store**, views an active package, then claims a free offer if eligible or selects **Continue to HitPay** when available. User sees owned grants, current saved balance, token activity and payment history. `PackageClaims` enforces per-account claims, offer status, limits and version. Grants can include time-limited use counts, unlimited benefits or eligible templates. `FeaturePricing` defaults to strict explicit package benefits. Individual token paths require feature-local configuration and explicit purchase; paused, stale, expired or depleted paths can deny access on the server.
2. `BonusCreditService` manages permanent saved tokens in `ai_bonus_wallets` and `ai_bonus_ledger`, including payment, reward, grant, spend and correction entries where applicable. `AiQuotaService` manages daily/base AI allowance and reservations plus `ai_token_activity`. `PackageAccess`, `FeaturePricing` and `TemplateAccess` resolve package use counts, individually purchased entitlements, credit holds and the template library. These inputs have different fulfillment and expiry rules; positive balances do not imply access to every feature.
3. HitPay is **implemented, disabled by default**, with deployment state **unknown**. `PaymentActions::paymentRoutes()` runs before the old commerce checkout stub. `HitPay::available()` requires mode, matching credentials/salt and an HTTPS return origin. `PaymentOrders::start()` reserves or reuses an order using request key and quote version, snapshots amount/currency/benefits, calls hosted checkout and validates the returned URL. The result page reads state. `paymentWebhook()` verifies the raw-body HMAC, then `PaymentOrders::applyEvent()` checks request ID, reference, mode, charge, amount and currency. Paid state, benefit grant, receipt and audit are transactional. Duplicate successful events can leave one fulfillment. Disabled configuration, changed quotes, declined/expired/unavailable links and confirmation lag have distinct paths.
4. Admin **Pricing** owns package display, free offers, action prices and payment history/analytics. **User accounts → Packages** allows add, adjust, replace and revoke, with explicit saved-token corrections. Scope on per-user package changes differs from Pricing's grant tool. Signed refunds update the amount in history; fulfilled benefits are reviewed and adjusted by staff. No provider reconciliation scheduler, webhook event journal, automatic refund clawback or recurring subscription/lifecycle code was found. Missing or out-of-order provider confirmation and interrupted remote checkout need reconciliation gates before live enablement. SGD sandbox success would not establish MYR acceptance. No currencies, credentials or live payments were changed.

## Privacy, access and test gaps

- Account fields, `resume_data` JSON, cover letters, recovery snapshots, profile/portrait images, ticket text and attachments, session metadata, payment references and coach preferences have distinct access/retention needs. Current photo writes use validated image data in private records. `SupportAttachments` keeps files in protected storage, verifies type/size/ownership and serves authorized downloads. Retain private storage on deployment. Verify access to legacy uploads separately, without inspecting personal files.
- `Http` enforces same-origin checks and session CSRF for conventional mutations. Google login uses its double-submit exception. Most owner routes constrain reads/writes by user. Strict package access runs in the dispatcher and document handlers. GET downloads force the origin check but bypass the generic mutation-CSRF path by method. Treat refresh, retries and duplicate request settlement as acceptance cases. Role and owner tests should exercise direct calls. `AdminAccess::allows()` recognizes explicit authenticated self-service/work queue exceptions and maps other prefixes to capabilities. Unknown prefixes resolve to `unassigned`, but a new action under an existing prefix automatically inherits that module's method-based permission.
- `OpenAIService` calls the Responses API with `store: false` and a pseudonymous safety identifier. `AtsService` minimizes resume context and server actions check sensitive text, but free text and professional history are still data leaving ReGen when AI runs. Mochi drafting context can use explicitly selected saved resume data. `LookupService` combines local institution data with optional external Wikidata location queries; avoid forwarding contact information as a lookup term. Project logging intends to exclude raw prompts/bodies, SQL and secrets. Scope application, reverse-proxy, mail-delivery, support and audit metadata in the retention review.
- No first-class career profile, JD analysis, resume version, saved job, job ingestion, application, interview practice or subscription owner was found. Existing history is recovery, commercial contracts are package grants/orders, and external job application is absent. See the [data mapping](04-data-migration-plan.md) before creating any schema.
