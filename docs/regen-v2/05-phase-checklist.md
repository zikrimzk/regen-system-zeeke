## Decisions before Phase 01

- **Baseline and test environment.** Identify the intended reviewed commit/artifact and what is currently deployed. The code audit used a dirty working tree based on `948a5bf`. Provide an isolated DB/runtime for authorized checks of migrations, Apache rewrites, direct URLs, sessions and real PDF workflows with synthetic accounts. Confirm whether the DirectAdmin target stays fixed for the first phases; the proposed design assumes it does.
- **Permissions and maintenance exceptions.** Confirm who may view private saved resumes, export full account data, read support files and inspect/restore document snapshots. Confirm which auth/recovery and signed-provider operations keep processing during maintenance. The proposed exception set preserves admin and maintenance access while gating the entire candidate app.
- **Phase ordering and commercial rules.** Confirm one preserved primary document with additive variants and explicit evidence import. Decide whether Phase 01 only baselines charged GET or also addresses any immediate operational exposure. Confirm which live provider features, pricing modes, paid/claim policies and checkout currencies are expected. Decide refunds and recurring subscription scope before Phase 10, and approve any job-source agreements before feed work.

## Risk register

| Risk and severity | Evidence or exposure | Mitigation and gate |
| --- | --- | --- |
| Resume/editor/AI behavior regression — High | Single-primary logic, JSON sanitizer, recovery generation, template unlocks, shared PDF and AI reservations are coupled. | 01 baseline known outputs. 04 full 16-design and cover-letter comparison, legacy writes and schema fixture. 05 provider failure/no-fabrication/no-auto-apply and repeat charge cases. |
| Route downtime and maintenance coverage — High | PHP dev/Apache differ, hard-coded feature/notification/return paths, incomplete page allowlist and early realtime dispatch. | 01 metadata-driven maintenance tests and operator carve-outs. 02 exact route/API aliases, old links and direct/back/refresh tests on both runtimes with rollback. |
| Partial schema upgrades and data migration — High | Working tree/production parity unknown, date/address coupling, grants and permission migration side effects. | Compare `information_schema` and aggregate business invariants on fresh and upgraded databases. Back up, use additive steps and dry-run resumable batches, verify restore, and record 01/03/11 checkpoints. |
| Payment or quota inconsistency — High | Charged GET, missed provider callback and manual refund entitlement adjustment. Checkout and live verification unknown. | 04 idempotent export operation and credit recovery. 10 signed/replayed events, quote snapshots, reconciliation, manual audit and provider sandbox test before enablement. |
| Personal data exposure — High | Documents, snapshots, tickets, mail metadata and AI context span DB, private files and providers. | Purpose-limited scopes, minified payloads, protected storage, consent/use proof, audit and retention/delete verification. Gates in 01, 05, 09 and 11. |
| Access-control regression — High | Page and API auth differ. Module-prefix scope needs explicit action intent. Account export can include full document data independent of template-view permission. | Review role capabilities, decide private-read/export/restore scope, enforce record ownership in query boundaries and test direct calls/denied access in 01 and 09. |
| Job source legality and freshness — High for ingest | No provider agreements or feed verification identified. | Phase 06 starts with user-saved links. Confirm permission, usage terms, attribution, freshness and retention before enabling any integration. |
| Performance and live-update load — Medium to high | Worker/shared hosting limits, synchronous PDF/AI, polling fallback, document JSON and unbounded letter list. | Measure staging concurrency, queue lag, index effectiveness, lists and provider/session locks. Add bounded paging/cache only with parity checks, establish acceptance baseline in 01 and release budget in 11. |

## Manual QA before expanding scope

- Candidate register/verify, resend failure, sign in/out, direct deep links, password reset, stale/revoked session and protected pages. Repeat signed-in/anonymous with maintenance scheduled, active and ended. Confirm admin access and callback ingress still behave as specified.
- Create and edit from a template, refresh after save, interrupt network mid-save, recover without losing unsent text during in-app redirects and check legacy draft conflict. Test all 16 design paths, entitled/locked preview and PDF, cover-letter create/edit/export/recovery and original stored fields.
- Assist, Refine, writing review and Mochi with enough evidence and deliberate consent. Exercise no evidence, disabled/empty, package and quota blocked, failure/refund, invalid response and user declines suggestion.
- Verify 360/390/768/1024/1440 px, iOS/Android software keyboard, low-motion and dark/light with keyboard-only admin and candidate actions. Try back, refresh, legacy `.html` with query/fragment, remembered choice, PWA offline and reconnect.
- Sign in as super admin and delegated support, pricing and template roles. Check private document denial/allowed audited access, role expiry, support attachment scope, pending counts, live replies with draft state, campaigns, mail/notifications, system settings and operation recovery.
- Test store/claim, token activity, package terms, insufficient/expired benefits, retries and idempotent adjustments. On an approved sandbox confirm paid/failed/expired/duplicate/refund paths and eventual reconciliation, with no production billing or email traffic.
