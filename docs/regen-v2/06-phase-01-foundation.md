## PDF exports and benefit accounting

- **User** keeps the current PDF generation, previews and pricing. **Admin** retains existing account package, token and order history views. Neither workflow adds credits on export or changes an existing grant.
- `CommerceActions::enforceTokenAccess()` forces an origin check for paid GET and reserves access with `FeaturePricing` and `PackageAccess`. The current render releases the session lock. `DocumentActions::completeDocumentDownload()` rechecks template access and settles the specific hold before bytes leave the server. Failed validation/rendering releases the hold at shutdown or it expires. Returning a held use does not refund the saved tokens already paid to purchase an individual credit. That uses the existing explicit refund operation.
- **Confirmed behavior to address.** Two successful requests to the same GET URL can consume two distinct eligible uses, including a browser retry after the first response was lost. Overlapping requests cannot both reserve the final use and a used reservation cannot be charged twice. The defect is the lack of a logical export operation ID across requests. Keep existing accounting in this phase. If addressed early, issue a client action UUID for a deliberate download and bind it to the candidate, document and document version on the server. Settle once and reuse the result for a retry of that UUID. Do not deduplicate merely by document or time window, since users may intentionally request two exports.
- The document phase should start the billable operation via CSRF-protected `POST` with a persistent unique owner/action ID. Track pending, released, succeeded and expired state, and serve the resulting private artifact via an authorised GET with no benefit reservation. Make artifacts expire and keep sensitive contents out of the URL and logs. Roll out after resume and letter PDFs, duplicate/failure recovery, concurrent requests and legacy callers pass parity checks. This phase changes no PDF routes, transaction logic or accounting schema. **Verification** checks overlapping holds through separate PDO connections, release/retry, two identical HTTP GETs, exhaustion and both resume and letter PDF streams.
