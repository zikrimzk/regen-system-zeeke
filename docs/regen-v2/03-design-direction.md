# Phase 00 · ReGen design direction

Retain the ReGen wordmark, restrained green, bundled Inter, recognizable document tools and the dark admin sidebar. `public/css/main.css` already has semantic surfaces, `theme.js` already supports light/dark/system and preference consent, and `WorkspaceShell.php` renders shared navigation. Build on these in later phases. Keep visual styling independent of the PDF design catalog and preserve the six existing document font families.

## Proposed interface tokens

| Token group | Values and use |
| --- | --- |
| Type | Inter/system. Body `16px/1.5`, compact `14px/1.5`, metadata `12–13px/1.4`, labels `14px/1.4` or `16px/1.5` for key fields. Page title `28px/1.25`, section title `20–22px/1.3`, dialog title `20px/1.3`. Use medium for labels, semibold for headings. Buttons `14px/1.4`. Marketing hero has its own responsive limit up to `48px`. |

| Light roles | Canvas `#F5F6F3`, surface `#FFFFFF`, raised/muted `#EDF1ED`, text `#17231D`, secondary `#445750`, divider `#D6DFD8`, primary `#166348` with white text, focus `#14634C`. |
| Dark roles | Canvas `#101714`, surface `#18221D`, raised/muted `#223028`, text `#EAF2EC`, secondary `#B6C7BF`, divider `#3B5146`, primary `#8BD3AE` with `#10251B` text, focus `#94DEB8`. ## Candidate screens

- **Public and auth.** Keep the landing task entry, sample design exploration and demo label. Use one main action for each marketing section. Sign-in and register share consistent form labels, provider alternatives when enabled, and clear field/server errors. Show the verification or resend status inline, where focus can reach it. Keep language and appearance options available without requiring an account.
- **Desktop workspace.** Compact header contains the ReGen logo, primary tasks, one inbox bell and account menu. Home opens with the next useful action, such as **Continue your resume**, its save state and a document link. Secondary actions take users to letters, career profile and jobs as those features ship. Use a section rail, input column and document preview for the editor where width permits. Reserve a stable location for save/retry status and a distinct export action with benefit cost if relevant. Assist/Refine results open in context with **Apply** and **Keep editing**; proposed changes cite existing evidence.
- **Phone workspace.** Use a labeled bottom navigation with Home, Documents, Jobs and Account once Jobs is enabled. Until then, use Store as a reachable account/destination option without empty tabs. Documents groups resumes, designs and cover letters. One top bar bell opens the inbox. In the editor use step navigation, one-column forms, sticky Save/Next above the safe area, and a distinct preview screen or dialog with a clear back action. Keep unsaved inputs in place through in-app reconnect and maintenance flows. Reverify Android and iOS keyboard, rotate, zoom, focus and PDF scrolling. Mochi remains reachable through Account/editor controls and yields to form focus, dialogs and reduced motion.
- **Visible states.** Loading reserves the expected space and indicates progress to assistive technology. An empty workspace offers template selection, an empty inbox explains where messages arrive, and an inactive or inaccessible feature shows a short reason with the next valid action. Errors remain near their fields, include retry/recovery or a safe support reference, and preserve unsaved fields when possible. Offline shows what is unavailable and a reconnect path. Payment confirmation uses pending, paid, failed and refunded copy aligned to actual order state. Show an optional reward only if records make it available.

## Admin screens

- **Desktop.** Dark, high-contrast sidebar with visible logo and one link per operational destination. Group Users, Support, Feedback and Campaigns, Documents and Pricing, and Settings/Operations. Put the three relevant views of Analytics under one parent. Represent session controls, health and recovery with dedicated URLs and current-view state. Show ticket/feedback work counts beside their owning links and use the header bell only for unread admin notices. Link account package history from the user detail and use a single governed service behind both grant entry points.
- **Mobile/tablet.** Named menu toggle opens a focus-managed drawer. Toolbar wraps search, status filter and action. Convert narrow table rows to labeled lists for accounts, tickets and order overview; allow horizontal table scroll locally where multiple columns are essential. Keep row actions close to the record and expose total/fetched count and pagination. Preserve selected filters and route on refresh/back. Scoped admins see authorized routes and useful empty/no-access outcomes, including access pending.
- **Operational forms.** Date/time fields display Kuala Lumpur time for a maintenance schedule and show start/end/recovery behavior. Provide explicit save, retry and stale-version states. Inbox updates counts and content without reload, and ticket replies preserve drafts during refresh. On connection failure distinguish delayed updates from confirmed empty data. Audit private-view actions and prevent private content from appearing in generic list previews.

## Bilingual and accessible behavior

- Maintain one translation key and explicit interpolation contract per label, status, error and permission message. Share keys between PHP-rendered controls and browser modules with a small generated or server-delivered dictionary. Use `en-MY` and `ms-MY` formatters, `<html lang>` and default English until the user chooses Bahasa Melayu. Make account locale optional, with appropriate persistence. Keep write errors machine-readable with localized messages. User-entered content and resume/letter language remain independent from interface language.
- Display `RM` for MYR with locale-aware formatting, actual currencies for order records, and clear time zone labels when relevant. Use `Asia/Kuala_Lumpur` for display and UTC for stored instants. Date-only records such as cover-letter dates retain the entered calendar day. Support SPM/STPM, TVET, certificates, diplomas, apprenticeships, degree and other routes, with flexible labels such as **Education & training**. Let AI language be explicit and keep mixed in-product bilingual strings to deliberate labels.
- Use semantic headings, real links, named dialogs, visible focus, status announcements and labels that survive collapsed navigation. A feature/plan lock has an explanation discoverable without a pointer. Verify contrast, focus visibility, zoom/reflow, accessible error summaries, targets and reduced motion against the project's WCAG 2.2 AA goal. Review translations with Malaysian candidates across the target career stages.

## Patterns to remove during feature work

| Current evidence and pattern | Proposed expression |
| --- | --- |
| `assist-me.js` repeats **Assist me** as a dialog eyebrow with a second heading. Landing includes section kickers and decorative feature numbers. | A single **Draft this section** title and one sentence only if instructions help. Marketing has a clear section title and a link to the action. |
| A green outline around every dashboard or package surface makes all items look selected. | Use neutral surfaces and separators. Reserve a colored outline for a selected template or a labeled warning/error. Keep price and eligibility visible through text. |
| `workspace-shell.css` uses dense 10 px nav labels and a 24 px confirmation heading alongside separate control sizes. Repeated local scale overrides make the type hierarchy uneven. | Use shared 14 px nav/control text, 20 px confirmation titles and 12–13 px only for metadata. Check Bahasa Melayu wrapping at 360 px. |

Acceptance includes all relevant widths and both themes, keyboard-only routes and dialogs, announcement/support updates, real save/download/preview and ownership-matched state.
